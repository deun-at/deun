# Notes / Ideas Backlog

Quick notes from Jakob (2026-07-24) — not yet refined into tasks.

## Bugs

### 1. Group save with multiple members fails but still saves broken group
- Saving a group with multiple members shows "error while saving", but the group is still created with `name = null`.
- The broken group then breaks the whole group list for **everyone** in the group.
- We fixed something like this before — root cause back then was roughly "the input field was not visible anymore" (form field disposed/off-screen so its value wasn't picked up).
- **Possible non-bug:** it may be that the earlier bugfix simply wasn't deployed yet. Verify what's actually deployed before re-debugging.

### 2. Removing a member gets confused
- When you remove a member from a group, the state/balances get confused. Needs investigation and a clear definition of what should happen to their expenses/shares.

### 3. Deleting an already-paid-back expense is confusing
- Deleting something that was already paid back leads to confusing balances. Needs a defined behavior (block deletion? reverse the payback? warn?).

## Ideas / Layout changes

### 4. Simplify group creation
- Creating a group should only ask for: **name + simplified/normal mode**.
- Member management should be moved out of the create flow.

### 5. Refactor adding members
- Adding members should be completely refactored into its own flow/screen.
- No design yet — needs a design session.

### 6. Owner can mark "is paid" for others
- As the group owner (ower), I want to set the "is paid" flag on behalf of guests or other members, so paybacks from people who don't use the app can be recorded.
