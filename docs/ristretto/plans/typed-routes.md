# typed-routes — Group and expense pages open from their URL, by id

## Spec
- Source: idea — code review 2026-10-22 (research/code-review-2026-10.md), architecture item: the 11 `state.extra as Map<String, dynamic>` casts in lib/navigation.dart (As-is row "for typed-routes"); the CODE_REVIEW_2026-07-07 §6 "leave alone" advice it cites is superseded
- Flight: structure
- Goal: Every group and expense page opens from its URL alone (web refresh, a pasted link, browser back/forward, a notification) by loading its group and expense by id, and an unknown id shows not-found instead of crashing.
- Why: group members on the web build, and Jakob as sole maintainer (research/code-review-2026-10.md, Why candidates) · noticed by: refreshing a group or expense page on the web, pasting its link or going back and forward shows that page again after a short load instead of a crash, and a link to a group that does not exist says "Page not found"

## Contract
- Acceptance:
  - [auto] Opening any group or expense route by its location with no prefetched object first shows a loading state, then the page for exactly the group (and expense) named in the path. This covers group detail, group form (edit), members, share sheet, settle-up, statistics, month sheet, new-expense editor, expense read view, expense editor and claim page. The category sheet, which needs only the group id, opens straight away with the category and window from its location. Proof: widget tests over the real route table with the loads faked. Each test asserts the page type and the ids of the group and expense the page was built with.
  - [auto] None of these routes throws on a bad id. Each of these shows the not-found state: an id whose load reports no row, an id that is not a UUID, and an expense whose group is not the group in the path. The not-found state's back action returns to the group list. A stale `/group/details` location and every one of its old child locations show "Page not found" and never crash.
  - [auto] A load that fails for any other reason shows an error state with Retry. Retry loads again and shows the page once that load succeeds.
  - [auto] Once a page opened by its location is showing, a later reload of its group that fails (a realtime refresh or an app resume) leaves the page on screen. It is never replaced by the loading, not-found or error state.
  - [auto] In-app navigation with the object at hand shows the page, with the data it was opened with, on the first frame after the transition, and never shows the route's loading state.
  - [auto] Every in-app entry point still opens the same page for the same group or expense.   - Path scheme -> group creation is `/group/new`. These are direct children of `/group/:groupId`: `edit`, `members`, `share`, `payment`, `statistics` (with children `month` and `category`), `expense/new`, `expense/:expenseId`, `expense/:expenseId/edit` and `expense/:expenseId/claim`. Edit, members and share move from children of `/group` (today) to children of the group, so a refresh rebuilds the group detail beneath them, as the in-app push from the group detail does. Editor and claim stay siblings of the read view, as today, so a refresh of either rebuilds list → group detail → page, without the read view an in-app push may have left beneath it. Literal segments (`join`, `new`, `expense/new`) are declared before the parameter routes they would otherwise match. `/group/join`, the friend and setting routes, `/privacy-policy`, `/contact` and `/update-password` keep their paths. Source: prep ruling.
  - Old static paths -> no aliases. `/group/details…`, `/group/edit`, `/group/members` and `/group/share` cannot carry an id. Each ends either in the loader's not-found state (the old segment lands in `:groupId` and fails the UUID rule) or, where no route matches (`/group/details/expense`, `/group/details/expense-detail`, `/group/details/claim`), in the router's existing `pageNotFound` errorBuilder. That builder is unchanged and keeps having no back action, as for any unknown URL today. Source: prep ruling.
  - Extra -> only an optional prefetched object, for instant render: a `Group` on group routes, an `ExpenseRouteExtra` on expense routes. It is read with a type test, never a cast. An extra whose id differs from the path is ignored, because the path is authoritative. No extraCodec: on web, go_router drops a non-JSON extra from browser history, so it is not restored after refresh or back/forward, and that is exactly the load-by-id case. Sources: Jakob in prep code-review-2026-10 (2026-10-24); prep ruling.
  - Loading and test seam (dimensions f, g) -> the group loads through the existing `groupDetailProvider(groupId)`. GroupDetail already watches that same instance, so a stack opened by URL fetches the group once and keeps its group_update_checker realtime refresh, with no new channel. The expense loads through the new `expenseByIdProvider`, which subscribes to nothing. This feature writes nothing, so it bumps no checker. The brief's "repository seam" is met at the provider that wraps each repository read: `expenseByIdProvider` wraps only `ExpenseRepository.fetchDetail`, and `groupDetailProvider`'s load is `GroupRepository.fetchDetail`. Tests override the two providers with fakes that count calls and throw for the failure cases. Provider overrides are the seam because the route table builds the pages itself and cannot take function-typed constructor overrides. Precedent: the `groupDetailProvider` overrides in test/pages/groups/group_member_add_flow_test.dart. injectable-repositories has no Depends with this feature: if it has landed first, `expenseByIdProvider` reads `expenseRepositoryProvider`'s instance instead of the static `ExpenseRepository.fetchDetail` and `groupDetailProvider` already reads the group repository provider; the tests still override the two loader providers. If this lands first, injectable-repositories re-points `expenseByIdProvider`'s body and keeps its name and shape (injectable-repositories plan, Decisions). Sources: Jakob in prep code-review-2026-10 (2026-10-24) ("widget tests with a repository seam"); prep ruling.
  - Later reloads -> a loader shows the page whenever its provider holds a value, and shows loading, not-found or error only while no value has loaded yet. Riverpod (3.2.1 in pubspec.lock) keeps the previous value through a failed reload, so the page stays up, but a default `when` (skipError false) would still swap in the error state. Without this rule, a page opened by URL, including an editor with unsaved input, would vanish on any failed realtime or resume reload, which an in-app-opened page never does. Source: prep ruling, from lib/pages/groups/provider/group_detail.dart `reload` (`AsyncValue.guard` on every group_update_checker event and resume).
  - Group on expense routes -> without a prefetched `ExpenseRouteExtra`, the group comes from `groupDetailProvider(groupId)`, not from the loaded expense's embedded group, so the read view, editor and claim page show the same group object as the page beneath them. An expense whose `groupId` differs from the path shows not-found. With a prefetched extra, its group and expense are used as they are. Source: prep ruling.
  - Not-found vs error -> the path ids are checked first. A path id that is not a UUID is not-found before any prefetched object is looked at or any load is made, so test fixtures use UUID ids. Group and expense ids are uuid throughout the RPCs in supabase/migrations/ (for example `_group_id uuid` and `_expense_id uuid` in 20260610120000_atomic_save_rpcs.sql), and the deep-link allowlist already requires a UUID groupId. The table DDL itself is not in the repo (schema-baseline). A load that reports no row (`PostgrestException` code PGRST116 from `.single()`, which RLS also produces for a group the user cannot see) is not-found. Any other failure shows the error state, whose Retry invalidates the provider. The live policies (dump 2026-10-24) back this. `group` SELECT is allowed only to a member, or to the group's creator by `user_id`, and `expense` SELECT only to members. A non-member therefore gets no row, but a creator who has since been removed still sees their group. Source: prep ruling; the manual check confirms the error code.

## Approach
- Tier: normal — two loaders with a value-first state rule, about 24 call sites in eleven lib files plus six test harnesses to move, and a router harness that must stub the shell and every page offline leave real sequencing and harness choices for a planner.
- Build bottom-up so that each layer is testable before any call site moves. Start with lib/app_paths.dart, which is pure: path builders and `ExpenseRouteExtra`. Then lift the route table verbatim out of `_NavigationScreenState.initState` into `buildAppRouter` in lib/app_router.dart and repoint screen_transition_test.dart; the suite should still be green before any path changes. Then change the paths and add the loaders. Each route's page builder becomes a `GroupRouteLoader` or `ExpenseRouteLoader` inside its own `MaterialPage`, whose builder constructs the same page as today, so pages keep their constructors and gain no async code.
- The UUID check runs first, then the prefetched object: with a matching one the loader returns the page at once and watches nothing. Otherwise it watches `groupDetailProvider(groupId)` (and `expenseByIdProvider(expenseId)`) and renders the page whenever a value is present. `isRowNotFound` is a pure predicate over `PostgrestException.code`.
- Router tests pump `buildAppRouter` with its own root key inside a ProviderScope that overrides the two loader providers, plus the providers that the shell (`friendshipListProvider`, `pendingFriendRequestCountProvider`), GroupList and each page read. Supabase is initialised against localhost, as 29 test files already do. Fixtures use UUID ids. Count load calls in the fakes, and throw `PostgrestException(code: 'PGRST116')` for the not-found cases. Pages whose own data cannot be stubbed offline are asserted by type and constructor ids right after load; the planner chooses per page.
- Then move the call sites one file at a time, along with the matching probe routes in their tests. Statistics and the receipt hand-off get their own tests because they carry data beyond an id. `openPushMessage`'s group case is last, and drops its pre-fetch.
- Likely touchpoints: lib/app_paths.dart (new), lib/app_router.dart (new), lib/widgets/route_loader.dart (new), lib/pages/expenses/provider/expense_by_id.dart (new, plus .g.dart), lib/navigation.dart, lib/push_notifications.dart, lib/helper/helper.dart (or lib/helper/navigation_helpers.dart after helper-split), lib/pages/groups/presentation/group_detail.dart, group_detail_edit.dart, group_list.dart, group_list_item.dart, group_join_page.dart, group_members_page.dart, lib/pages/expenses/presentation/expense_detail_read.dart, claim_page.dart, lib/pages/statistics/group_statistics_page.dart, test/widgets/screen_transition_test.dart, the six router-probe test files, test/app_router_test.dart (new), test/widgets/route_loader_test.dart (new), docs/ristretto/manual-checks.md
