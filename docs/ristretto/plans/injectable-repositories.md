# injectable-repositories

## Spec
- Source: idea — code review 2026-10-22 (research/code-review-2026-10.md), architecture item `injectable-repositories` (As-is lines tagged "for injectable-repositories"; Open item on the CODE_REVIEW_2026-07-07 §6 "leave alone" advice)
- Goal: The app reads "who is signed in" from one provider, models are told the user instead of reading global auth, and the repositories become Riverpod-provided instances over a `SupabaseClient`, so tests override providers instead of initializing Supabase and an account switch cannot leak the previous user's identity.
- Why: Jakob as sole maintainer · noticed by: the backend rebuilds from supabase/migrations/, the fallback code paths are gone, the 1500–1900-line files open in pieces

## Approach
- Build bottom up so each step compiles and is green on its own. First add `CurrentUser`, `supabaseClientProvider` and `currentUserProvider`, and prove them with a controllable `authStateChangesProvider` (the harness of test/provider/auth_switch_invalidation_test.dart, minus the listener). Then add the email parameter to the three `loadDataFromJson`s and let the compiler list every caller. Then add `MemberDisplay` and swap the copies. Then move the remaining auth readers, converting seam owners to Consumers, and switch those widget-test harnesses to a `currentUserProvider` override.
- Next, the repositories, leaf first: reminder, user, expense, then the group/member/payback split, then friendship over the group repository. For each one, delete the statics, add the provider, and fix the call sites the compiler reports: notifiers `ref.watch` the provider in `build`, and widgets resolve their seam defaults through `ref.read`. The Depends plans' static seams become constructor parameters in the same step.
- Finish with the end-to-end tests: the account switch, same-user refresh and the favourite star, over repository fakes injected through providers. Delete the `Supabase.initialize` calls that only served auth or repository reads, and add the manual-checks entry.
- Tier: normal — six units across most of lib/, a three-way repository split, provider wiring for every notifier and seam owner, and sequencing against seven open plans leave real choices for a planner.
- Estimate 21, at the split threshold. Proposed split line, not applied: Units 1–4 (current user, models, member display, readers) ship as one feature that leaves the repositories static; Units 5–6 (repositories, call sites and proof) follow as a second.
- Sequencing: this edits most of lib/, so it lands after group-model-parse-safety (see Decisions), presentation-file-split, expense-editor-split, push-session-lifecycle, typed-expense-draft, editor-failure-keeps-form, realtime-channel-lifecycle and legacy-fallback-removal where possible. Whichever lands second rebases. The allowlist and seam rulings above say what to do in either order.
