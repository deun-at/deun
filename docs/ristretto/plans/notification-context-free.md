# notification-context-free

## Spec
- Source: idea — code review 2026-10-22 (research/code-review-2026-10.md), review finding 3 (client half); As-is lines tagged "for notification-context-free"; Open item "Settle-all with a friend sends no push today"
- Goal: Every push is composed from strings captured before the first network round trip and sent through one service, so a screen that closes early no longer drops it, and settling up with a friend finally tells the friend.
- Why: push recipients (research/code-review-2026-10.md, Why candidate) · noticed by: an expense push still arrives when its sender has reduce-motion on or leaves the screen quickly; a friend is told when everything owed to them is marked as paid

## Contract
- Acceptance:
  - [auto] A push is still sent when the screen that issued it is gone before its lookup returns. This covers the four kinds whose text is resolved after a lookup today: member added to a group, payback recorded, payment reminder and expense created. For each, a send issued while a widget is mounted, whose lookup completes only after that widget has been unmounted, still sends exactly one push with the expected type, object id, receivers, title and body. Today that late lookup reads `AppLocalizations` from the unmounted element and the push is silently dropped. With reduce-motion on, the expense editor pops at `Duration.zero`, so its lookup loses that race.
  - [auto] Every kind sends what it sends today. Listed as type · object id · title · body, checked against fixed lookup rows in English:
    - member added: `group` · group id · `groupNotificationTitle(<group creator's display name>)` · `groupNotificationBody(<group name>)`
    - payback recorded by the payer: `group` · group id · `groupPayBackNotificationTitle(<payer>, <group name>)` · `groupPayBackNotificationBody(<amount>)`
    - payback recorded on someone's behalf: `group` · group id · `groupPayBackOnBehalfNotificationTitle(<recorder>, <group name>)` · `groupPayBackOnBehalfNotificationBody(<payer>, <payee>, <amount>)`
    - payment reminder: `reminder` · group id · `reminderNotificationTitle(<group creator's display name>)` · `reminderNotificationBody(<amount>, <group name>)`
    - expense created: `expense` · expense id · `expenseNotificationTitle(<expense creator>)` · `expenseNotificationBody(<expense name>, <group name>, <amount>)`
    - claim nudge: `expense` · expense id · `claimNudgeNotificationTitle(<sender's roster display name, or the localized "you" when the sender is not on the roster>)` · `claimNudgeNotificationBody(<expense name>, <group name>)`
    - friend request / friend accepted: `friendship` · empty object id · `friendRequestNotificationTitle` / `friendAcceptNotificationTitle` · the matching body carrying the sender's own display name
  - [auto] A push shows its amount in the group's own currency. A payback, reminder or expense push from a JPY group shows a yen amount with no minor digits. A lookup row with no currency falls back to the default currency, as it does today.
  - [auto] The text is written in the sender's app language. The same expense-created push from a sender whose app runs in German carries the German title and body.
  - [auto] The body posted to the `push` Edge Function keeps today's shape: `type: 'INSERT'`, `table: <type>`, and a `record` of type, object_id, title, body and notification_receiver. The signed-in sender's own email is removed from notification_receiver.
  - [auto] Receivers are unchanged. The payback receivers are already enforced by test/model/payback_request_test.dart ('both parties are notified when the payer is a real user', 'a guest payer is not notified — only the payee is', 'a self-payback still reaches only the payee once the recorder is stripped'). The member-added gate is enforced by the four tests in the `shouldNotifyAddedMember` group of test/model/member_add_test.dart ('a real user who joined (inserted) is notified', 'a real user who re-joined (reAdded) is notified', 'a guest is never notified, even when inserted', 'an already-member add announces nothing'). The claim nudge's type, object id and receivers are enforced by 'F175: tapping Nudge sends an expense push to the members' in test/widgets/claim_nudge_test.dart. All three files must stay green, unedited.
  - [auto] Settling everything with a friend sends the friend one payback push per group that was actually settled. Each push has the same type, object id and copy a single settle-up sends, with that group's amount in that group's currency. A group the run skipped sends nothing. A group whose write throws sends nothing. The other groups whose writes succeed still send theirs, and the run still fails to its caller, as it does today. Today `payBackAll` passes `sendNotification: false`, so the friend hears nothing.
  - [auto] No send ever throws to its caller:
    - With nobody signed in, the friend-request and friend-accepted sends complete normally and send nothing. Today `currentUser!` throws.
    - When a lookup fails, every kind that looks something up completes normally and sends nothing.
    - When the push function itself throws, the send still completes normally.
  - [auto] The expense editor's save and the friend sheet's Mark as paid behave as before. test/widgets/expense_save_status_test.dart, test/widgets/expense_editor_currency_rate_test.dart and test/widgets/friend_detail_sheet_test.dart stay green with only their seam stubs' signatures changed: no assertion is removed or weakened. test/widgets/record_payback_sheet_test.dart and test/pages/groups/group_member_add_flow_test.dart stay green, unedited.
  - [auto] `dart format`, `flutter analyze` and `flutter test` pass.

- Decisions:
  - Scope: only the client half of review finding 3. Text is still composed on the client, in the SENDER's language. Composing on the server in the receiver's language belongs to push-server-compose (Jakob in prep code-review-2026-10 (2026-10-24); research/code-review-2026-10.md).
  - Root cause: helper.dart's group, payback, reminder and expense senders call `AppLocalizations.of(context)` inside `.then`, after a select (research/code-review-2026-10.md). save-status-rollout made this lethal under reduce-motion: `reducedIfNeeded(Motion.saveConfirmationHold)` collapses to `Duration.zero`, so the editor pops before the select returns (save-status-rollout).
  - No BuildContext crosses an await on any notification path. The `AppLocalizations` is captured synchronously, at the latest where the send is issued. Wherever a handler awaits before it sends (editor save, payback sheet, settle-up, settle-all, reminder, friend accept/request), the capture happens before that handler's first await (Jakob in prep code-review-2026-10 (2026-10-24)).
  - One service, lifted rather than copied. The six live `send*Notification` functions and `sendNotification` move out of lib/helper/helper.dart into lib/helper/notification_sender.dart, and no forwarding wrappers stay behind. The claim nudge, which composes inline in claim_page.dart today, also composes through the service. That leaves helper-split less to move (Jakob in prep code-review-2026-10 (2026-10-24)).
  - Repositories take no BuildContext. `payBack`, `payBackAll` and `saveAll` receive a `NotificationSender` instead (Jakob in prep code-review-2026-10 (2026-10-24)). It is `required`, not nullable, so a call site that forgets the push fails to compile instead of going silent. That is the "same receivers as today" ruling, held by the compiler.
  - Constructing a `NotificationSender` touches no Supabase client. The default transport and lookups reach `supabase` only when a send runs. expense_save_status_test.dart and friend_detail_sheet_test.dart build the editor and the friend sheet without initializing Supabase, and both screens now build a sender before their stubbed write (follows from the ruling above and the "stay green" criterion).
  - Lookups: one group row serves member-added, payback and reminder. The member-added and reminder selects today differ only by `currency_code`. The payback push reads only the group's name and currency, which it fetches today through the payback expense, so it now reads them from the group by id. This also means it never depends on that expense's `user_id`. One expense row, today's expense-created select, serves expense-created. The text read is identical (Jakob in prep code-review-2026-10 (2026-10-24), "same text"; research/code-review-2026-10.md As-is helper.dart).
  - Landing order with typed-expense-draft: neither depends on the other. If it lands first, `saveAll` and `ExpenseSaver` take its `ExpenseDraft` where the map stands in Provides, and this feature only removes the leading `BuildContext` and adds the trailing `required NotificationSender notifications` named parameter, giving `saveAll(String groupId, String? expenseId, ExpenseDraft draft, {required Currency currency, ExpenseConversion? conversion, required NotificationSender notifications})`. A context is never re-added (typed-expense-draft plan, Decisions; research/code-review-2026-10.md tags `saveAll` for both).
  - Landing order with payback-atomic-recalc and legacy-fallback-removal: no Depends in any direction, and all three edit `payBack`. The write half of the split carries whatever RPC sequence `payBack` has at build time: the client `update_group_member_shares` call and its retry until payback-atomic-recalc removes them, and the memoized `pay_back` fallback until legacy-fallback-removal removes it. This feature moves those calls into the write half unchanged and removes none of them. If payback-atomic-recalc's `payBackRpcOverride` already exists, every RPC of the write half keeps going through it, and `payBackAllWriteOverride` replaces the whole per-target write above it (payback-atomic-recalc and legacy-fallback-removal plans, Decisions).
  - Landing order with editor-failure-keeps-form and scan-total-applies: neither depends either way. If editor-failure-keeps-form's write-then-pop helper has landed, the editor builds the sender before it calls the helper, beside the validation gates, never inside the helper's write. Saver stubs that suites added before this feature lands (the saver injected in test/widgets/expense_editor_delete_guard_test.dart by editor-failure-keeps-form, test/widgets/expense_editor_rescan_test.dart by scan-total-applies, typed-expense-draft's hand-over test) get the same signature-only edit as the suites named in Acceptance, with no assertion removed or weakened (editor-failure-keeps-form and scan-total-applies plans).
  - `payBack`'s `sendNotification: bool` is removed. Its only `false` caller was `payBackAll`, which now sends (Jakob in prep code-review-2026-10 (2026-10-24), settle-all ruling).

## Approach
- The defect is the shape all four group senders share (select, then `.then`, then a context lookup), not any single sender. So the fix is a holder of already-resolved strings, not more `mounted` checks.
- Build `NotificationSender` first and prove it alone. The reproduction is a widget test: build the sender inside a `Builder` with a spy transport and gated row lookups, unmount the tree, release the lookup, and expect the push. Then delete the helper.dart senders and let the compile errors list the call sites.
- Split `GroupRepository.payBack` into its write (plan, RPCs, expense id) and a notify step. `payBackAll` then runs that same notify step for each settled target after that target's own write, which makes the copy identical by construction. `resolvePayBackAll` already computes each group's accepted plan (receivers, display names) and throws it away; `PayBackAllTarget` can carry it instead.
- In the editor, `_saveExpense` builds the sender beside its synchronous validation gates, before `setState(busy)` and the await. That is the spot where reduce-motion used to lose the push.
- Tier: normal — a new service, three repository signatures, a payback write/notify split with a fan-out seam, and ten call sites across nine screens leave real sequencing and seam-shape choices for a planner.
- Likely touchpoints: lib/helper/notification_sender.dart (new), lib/helper/helper.dart, lib/pages/groups/data/group_repository.dart, lib/pages/expenses/data/expense_repository.dart, lib/pages/expenses/presentation/expense_detail.dart, lib/pages/expenses/presentation/claim_page.dart, lib/pages/groups/presentation/record_payback_sheet.dart, lib/pages/groups/presentation/group_detail_payment.dart, lib/pages/groups/presentation/group_members_page.dart, lib/pages/friends/presentation/friend_detail_sheet.dart, lib/pages/friends/presentation/friend_list.dart, lib/pages/friends/presentation/friend_accept_page.dart, lib/pages/friends/presentation/friend_add_page.dart, lib/l10n/app_en.arb, lib/l10n/app_de.arb (plus the generated files), test/helper/notification_sender_test.dart (new), test/model/group_repository_test.dart, test/widgets/expense_save_status_test.dart, test/widgets/expense_editor_currency_rate_test.dart, test/widgets/friend_detail_sheet_test.dart
