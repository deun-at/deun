# expense-search-escape

## Spec
- Source: idea — code review 2026-10-22 (research/code-review-2026-10.md), As-is "expense_repository.dart `fetchData` `ilike('name', '%$filter%')` (25) unescaped" and "friendship_repository.dart precedent strips `%_,()\`"; Open item "expense-search-escape: strip `%`/`_` or escape them"
- Goal: Every character typed into a group's expense search matches only itself. No character acts as a wildcard, and no input makes the search fail.
- Why: group members using the app · noticed by: a failed save or delete no longer throws away the form, a retried payback no longer double-records, a joining guest no longer rewrites history outside the group

## Contract
- Acceptance:
  - [auto] Searching `50%` finds an expense named "50% off" and does not find "500 EUR" or "50 EUR". Searching `a_b` finds "a_b" and does not find "axb".
  - [auto] Searching `a*b` finds "a*b" and does not find "ab", "aab" or "a long b".
  - [auto] A backslash matches only a backslash. `a\b` finds "a\b" and not "ab". A trailing `50\` finds "50\" and not "50%".
  - [auto] Each of the characters `\ . ^ $ * + ? ( ) [ ] { } |`, typed alone or inside text, matches only itself: `.` finds "v1.2" and not "abc", and `(1` finds "Taxi (1)". An unbalanced `(`, `[` or `{` never makes the search fail.
  - [auto] Ordinary text still finds what it found before. Letters, digits, spaces, umlauts and emoji match themselves, and the match ignores case: `TAXI` finds "Taxi" and `müller` finds "Café Müller".
  - [auto] Text typed into a group's expense search reaches the server only in its escaped, literal form. It is never placed raw inside a like/ilike pattern on the expense name.
  - [ ] [human] On the live instance, searching a group for `50%`, `a_b`, `a*b`, `(1`, `[`, `\`, `TAXI` and `müller` returns exactly the expenses whose names contain that text (case ignored), with no error.

Search for `50%`, `a_b`, `a*b`, `(1`, `[`, `\`, `TAXI` and `müller`. Confirm that each search returns exactly the names containing that text (case ignored) and that no error is shown.
  - [auto] `dart format`, `flutter analyze` and `flutter test` pass.
- Provides:
  - `literalSearchFilter(String typed): ({String operator, String value})`, in lib/helper/search_filter.dart. `operator` is always `imatch`. `value` is `typed` with each of the 14 ARE metacharacters `\ . ^ $ * + ? ( ) [ ] { } |` preceded by one backslash and every other character left unchanged. Under PostgREST `column=imatch.value` it matches exactly the rows whose column contains `typed` as a substring, ignoring case. Usable with postgrest-dart's `filter(column, operator, value)` on any text column.
- Consumes: —
- Decisions:
  - Strip or escape -> escape. `%` and `_` match literally: "50%" finds "50% off", and "a_b" matches only a literal underscore. Ruled by Jakob in prep code-review-2026-10 (2026-10-24), settling the Open item in research/code-review-2026-10.md.
  - `*` -> In like/ilike values, PostgREST rewrites every `*` to `%` before Postgres sees it, and there is no way to escape it. Source: PostgREST src/library/PostgREST/Query/SqlFragment.hs, `star`, applied only to OpLike/OpILike, read at main on 2026-10-24. No like/ilike pattern can match a literal `*`, and an escaped `\*` would arrive as `\%`, which is a literal percent sign. Jakob in prep code-review-2026-10 (2026-10-24) asked that every typed character match literally, so the search moves from `ilike` to `imatch` (Postgres `~*`), which PostgREST passes through unrewritten (same file: OpMatch/OpIMatch take the default branch).
  - Backslash -> In LIKE, the backslash is Postgres's default escape character (Postgres docs §9.7.1), which is why `a\b` finds "ab" today. In the regex it is escaped like the other metacharacters, so it matches itself. Source: Jakob in prep code-review-2026-10 (2026-10-24), every typed character matches literally.
  - Escape set -> exactly the 14 characters listed above, each preceded by one backslash. In a Postgres ARE, `\` before a non-alphanumeric character means that character literally (Postgres docs §9.7.3, regular expression atoms). Letters and digits are never escaped, because `\d`, `\m` and similar are class or constraint escapes in an ARE. `%`, `_`, space, `-`, `#` and all non-ASCII characters pass through unchanged, since none of them is special outside a bracket expression, and no bracket expression is ever produced. Because `(`, `?` and `*` are always escaped, no input can form an embedded option `(?…)` (which could switch on expanded mode, where `#` and spaces become special) or a `***:`/`***=` director.
  - The `***=` literal-string director is rejected. A single prefix would do the same job, but it is Postgres-only and opaque to the Dart RegExp proxy, while escaping per character can be tested one character at a time. Source: Jakob in prep code-review-2026-10 (2026-10-24), a pure escaping function with unit tests is the proof.
  - Proof -> the five matching criteria are proven in test/helper/search_filter_test.dart: the exact `value` and `operator` returned by `literalSearchFilter` are asserted, then `value` is matched against the sample names through the Dart RegExp proxy below. This proves what the client sends; what the live PostgREST and Postgres do with it is the [human] criterion. Source: Jakob in prep code-review-2026-10 (2026-10-24), a pure escaping function with unit tests is the proof.

## Approach
- Tier: easy — the contract pins the one new file, the function's name and record signature, the escape set, the operator, the single call site, the test file with every input and sample name, and the manual-checks entry. A planner would add nothing.
- Today the group search passes the raw text to `ilike('name', '%$filter%')`. In that pattern `%` and `_` are LIKE wildcards, `\` is the LIKE escape character, and PostgREST rewrites `*` to `%`. So "50%" also finds "500 EUR", "a*b" finds "a long b", and "a\b" finds "ab". Escaping inside LIKE cannot fix `*`, because PostgREST rewrites it before any escape can apply. The search therefore moves to a case-insensitive regex match, where only the 14 ARE metacharacters are special and each can be escaped. `%` and `_` stop being wildcards because a regex treats them as ordinary characters, and `*` because it is escaped and PostgREST does not rewrite it for imatch. Write the pure function test-first, with exact-value assertions and the Dart RegExp proxy. Then switch the name filter in `fetchData` to it and add the source-shape guard. `fetchData`'s signature, the `is_paid_back_row` exclusion, ordering and paging stay unchanged, and so does the caller in group_detail.dart (345).
