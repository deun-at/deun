# group-model-parse-safety

## Spec
- Source: idea — code review 2026-10-22 (research/code-review-2026-10.md), finding 9
- Goal: A malformed `group_shares_summary` row or a null `simplified_expenses` never leaves a `Group` or `GroupSharesSummary` with an unset field. The group still loads, and its other rows still count toward its balances.
- Why: group members using the app · noticed by: a failed save or delete no longer throws away the form, a retried payback no longer double-records, a joining guest no longer rewrites history outside the group

## Approach
- Tier: easy — the change is in one lib file, the two test files are named, every fixture and expected value is pinned in Acceptance, and every ruling is made. There is no migration, copy or UI, so a planner would add nothing.
- Strategy: the defect is a parse that is all-or-nothing per group but fails partway through. The fix makes each row survive on its own. Bad numbers read 0, a missing name reads the email, a row with no email is skipped. The fields that the guard could leave unset become default-initialised, so even an unforeseen throw leaves readable zeros instead of LateInitializationError. Write the red tests first in group_settlement_test.dart using the explicit-email seam. Then add the new no-Supabase file for the `simplified_expenses` and guard cases. Then make the three units green in order. Keep the settle-residue rounding exactly where it is: once per counterparty, after accumulation. The settlement loop, `amountToSettleWith`, `PaymentPartition` and the friend list read the same fields unchanged.
