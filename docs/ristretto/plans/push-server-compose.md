# push-server-compose — The push function writes each push for its receiver and checks who may get it

## Spec
- Source: idea — code review 2026-10-22 (research/code-review-2026-10.md), review finding 3 (server half) + architecture item; the As-is lines tagged "for push-server-compose"; Open item "The `push` function's server contract … is inferred from the client only"
- Flight: backend-in-repo
- Goal: The `push` Edge Function, recovered into the repo, writes every push itself in each receiver's language and delivers it only to people who share that push's group or friendship with the signed-in sender.
- Why: push recipients · noticed by: no push on a device after its user signed out; text arrives in the receiver's language; only members of a shared group can be targeted

## Contract
- Acceptance:
  - [auto] Every kind reaches the server with what it needs to write the push, and with no title and no body. That is its kind, today's routing type and object id, the receivers with the signed-in sender's own email removed, and the values its text needs that no row holds: the amount (the same number today's text shows) for a payback, a reminder and a new expense, plus the payer's and the payee's emails for a payback. If this goes red, the server cannot write the push and the receiver never gets it, or sender-written text still travels (unit test over `pushRequestBody` and a spy transport, one case per row of the wire table in Decisions).
  - [auto] Every kind the client can send is one the server can write, with the same routing type (Dart test parsing the server's kind table against `PushKind`). If this goes red, a kind the server does not know is refused and the push silently never arrives, or a mismatched type opens the wrong screen on tap.
  - [auto] Tapping a push still opens what it opens today. The function puts the kind's routing type in data['type'] and the object id in data['expense_id']: the group id for `group` and `reminder`, the expense id for `expense`, empty for `friendship` (source-shape test over supabase/functions/push/index.ts). The client half is already enforced by push-session-lifecycle's `pushTargetFor` unit tests (test/push_notifications_test.dart, created by that feature), which must stay green.
  - [auto] A receiver gets every kind in their own language, worded as today. Every kind has an English and a German title and body, each equal to the ARB string under the same key in lib/l10n/app_en.arb and lib/l10n/app_de.arb, the payback's on-behalf pair included, and every placeholder in every template has a binding (Dart test parsing the kind table and both ARB files). If this goes red, a German receiver gets English, empty or outdated text.
  - [auto] The language is the receiver's stored language, never the sender's. Each kept receiver's push is written from that receiver's own `user.locale`: German when its language subtag is `de`, English for null, `en` or anything else. Nothing in the request chooses the language (source-shape test over index.ts). If this goes red, a receiver reads the push in the sender's language.
  - [auto] Every name in a push belongs to the right person. Every title that names someone names the signed-in caller: the member who added, the payer recording their own payback, the recorder of an on-behalf payback, the member sending the reminder, the expense creator, the nudger. The friend bodies also name the caller. The on-behalf copy is chosen exactly when the caller is not `paid_by`, and its body names the people stored for the two emails that were sent. Apart from the amount, nothing a person reads in a push comes from the request (bindings in push_kinds.json checked by the Dart test; variant choice pinned by source shape). If this goes red, a receiver is told the wrong person acted. Today the member-added and reminder titles name the group's creator instead.
  - [auto] Amounts show in the group's currency, with that currency's own number of decimals. The server's zero-decimal currencies are exactly the `kSupportedCurrencies` codes whose `decimalDigits` is 0 (JPY, ISK and KRW at HEAD; every other supported code has 2). Amounts render as "<CODE> <number>", with the receiver locale's grouping and decimal mark, the way `formatMoney` renders them. A group with no currency code falls back to EUR (Dart test over the JSON; format and fallback pinned by source shape). If this goes red, a yen amount shows "JPY 3,000.00" or a push shows the wrong currency.
  - [auto] Only a signed-in caller can send a push. The function gets the sender only from the request's bearer token, through the auth server, and never from a field in the request body. A request with no user, such as one made with the anon key that the web build ships, sends nothing and gets an error back. So does a request with an unknown kind (source-shape test over index.ts). If this goes red, anyone holding the public anon key can push arbitrary members' devices.
  - [auto] Only people who share the push's group or friendship with the caller receive it (source-shape test over index.ts):
    - Group kinds (`member_added`, `payback_recorded`, `payment_reminder`) are checked against the group in object_id. Expense kinds (`expense_created`, `claim_nudge`) are checked against the expense's group.
    - If the caller is not an active member of that group (a group_member row whose `removed_at` is null), nothing is sent. Each receiver is kept only if they are an active member of it.
    - A payback whose `paid_by` or `paid_for` is not an active member sends nothing.
    - The friendship kinds keep a receiver only if a friendship row links them to the caller, in either direction.
    - The caller never receives their own push.
    - If this goes red, a push reaches a stranger or a soft-removed member. Today the claim nudge already reaches removed members.
  - [auto] No credential is committed. Nothing under supabase/functions/push/ holds a private-key block, a service-account `"private_key"` field, an FCM server key, a JWT-shaped literal or a `Bearer` token literal. Credentials are read from the environment (Dart scan over the folder). If this goes red, a committed FCM credential lets anyone push to every device.
  - [auto] Client sends keep their guarantees:
    - These already-enforced guarantees stay: a send never throws to its caller, nothing is posted when nobody is signed in, a push still goes out after the issuing screen is gone, and settle-all sends one payback push per settled group.
    - They are enforced by notification-context-free's suites: test/helper/notification_sender_test.dart (created by that feature), the settle-all cases in test/model/group_repository_test.dart, test/widgets/friend_detail_sheet_test.dart, test/widgets/expense_save_status_test.dart and test/widgets/expense_editor_currency_rate_test.dart. These stay green with only their `NotificationSender` construction and their spy transports' shape changed; `ExpenseSaver` and `FriendSettleAll` keep their signatures, so those stubs do not change.
    - Their type, object id, receiver and amount assertions stay. Their title, body, German and JPY assertions move to the server criteria above and are not dropped.
  - [auto] Receivers are unchanged, which is already enforced by tests that must stay green, unedited:
    - test/model/payback_request_test.dart: 'both parties are notified when the payer is a real user', 'a guest payer is not notified — only the payee is', 'a self-payback still reaches only the payee once the recorder is stripped'.
    - The four tests in the `shouldNotifyAddedMember` group of test/model/member_add_test.dart.
    - test/widgets/record_payback_sheet_test.dart and test/pages/groups/group_member_add_flow_test.dart.
    - 'F175: tapping Nudge sends an expense push to the members' in test/widgets/claim_nudge_test.dart also stays green. Its spy changes to the new transport: the type, object id and receiver assertions stay, and the two non-empty title/body assertions become an assertion that the kind is `claim_nudge`.
  - [auto] `dart format`, `flutter analyze` and `flutter test` pass.
  - [human] A real push arrives on a device in the receiver's language, with the group's currency formatted for that language, while the sender's app runs in the other language.
  - [human] A receiver who shares no group with the sender, or who was soft-removed from the push's group, gets nothing, while a current member named in the same push gets it. A request made without a signed-in user delivers nothing.

  - Schema facts for the server reads: `user.locale` is text and nullable, as the Receiver locale ruling expects. `group.currency_code` is `NOT NULL DEFAULT 'EUR'`, so the EUR fallback stays as a guard but never fires on a live row. `group_member.removed_at` and `friendship(requester, addressee)` exist as the Membership rule reads them.

## Approach
- Tier: normal — recovering source nobody in the build has seen, a server change provable only by source shape and JSON parity, and a client reshape across ten call sites leave real sequencing and anchor-shape choices for a planner.
- Start by copying supabase/remote_dump/functions/push/index.ts (main checkout) into supabase/functions/push/. Commit it untouched apart from the credential swap, then change it in place rather than rewriting it, so the token lookup, the FCM call and the stale-token delete stay as the deployed copy runs them. The recovered copy and the live catalog show no caller other than the app (Blockers).
- Move everything declarative out of TypeScript into push_kinds.json: each kind's routing type, scope, ARB keys, en/de templates and placeholder bindings, plus the zero-decimal currencies. Dart can then prove copy, kind and currency parity exactly. The TypeScript that cannot run in the gates shrinks to a small interpreter whose guards are pinned by source shape, as exchange_rate_function_test.dart pins the exchange-rate function.
- index.ts then runs, in order: resolve the caller from the bearer token (refuse if none); look up the kind (refuse if unknown); resolve the scope — the group, the expense's group, or the friendship rows — and refuse if the caller is not an active member; filter the receivers; read each kept receiver's locale, the display names and the tokens; write the push once per receiver from the table and send it with today's data keys; delete the token rows FCM reports as unregistered.
